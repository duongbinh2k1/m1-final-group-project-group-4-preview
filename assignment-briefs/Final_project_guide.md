# 🎓 Final Project Guide

## From Sensor to User & Security and Ethics for Data

## 1. Overview

The final project is the final integration of all course topics. Students are required to design and present an **AIoT system** that covers the full data lifecycle:

**Sensors → Data Collection → Transmission → Processing → Decision → User Interaction**

At the same time, the system must integrate **security, privacy, and ethical considerations** from the beginning, not as an afterthought.

## 2. Methodological Framework

All projects must follow the **Meta-Framework**, which consists of four pillars:

### 🔹 PEAS (Problem Definition)

*   **Performance**: What defines success?
*   **Environment**: Where does the system operate?
*   **Actuators**: What actions are performed?
*   **Sensors**: What data is collected?

### 🔹 STA (System Thinking & Analysis)

*   Environmental constraints
*   Technical risks
*   Failure points
*   Mitigation strategies

### 🔹 DIKW (Data to Decision Pipeline)

*   Data → Information → Knowledge → Decision
*   Focus on how raw sensor data becomes actionable insights

### 🔹 S\&E (Security & Ethics)

*   Security by design
*   Privacy by design
*   Ethical responsibility and social impact

👉 These four components must be integrated throughout the entire project.

## 3. Project Scope and Requirements

Each group must:

*   Select a **real-world IoT scenario**, preferably with constraints:
    *   Harsh environments (industrial, agriculture, remote areas)
    *   Limited power, connectivity, or reliability conditions

*   Develop a **minimum viable solution** including:

### ✅ Required Components

1.  Problem description and stakeholders
2.  PEAS analysis
3.  STA analysis (constraints and risks)
4.  DIKW data flow description
5.  System architecture (hardware + software)
6.  Data collection, transmission, processing solution
7.  Visualization / alert / decision mechanism
8.  Security and ethics assessment (S\&E)
9.  Working prototype or simulation evidence

👉 Students must clearly justify:

*   Whether **Edge AI is used or not**
*   Benefits and responsibilities of that choice

## 4. Project Development Timeline

Projects must be developed in **4 milestones**:

### 🟢 Milestone 1 – Problem Definition

*   Define:
    *   Problem
    *   Users
    *   Context
    *   Expected value
*   Complete **PEAS analysis**

### 🟡 Milestone 2 – Data Pipeline & Early Testing

*   Build:
    *   Data preprocessing pipeline
    *   Feature extraction
    *   Model testing (if ML/AI is used)

*   Use **sample or public datasets** if real data is unavailable

*   Evaluate feasibility before deployment

### 🟠 Milestone 3 – System Design & Risk Analysis

*   Provide:
    *   System architecture diagram
    *   Hardware/software selection
    *   Communication protocol
    *   Data flow

*   Apply **STA**:
    *   Constraints
    *   Failures
    *   Risks
    *   Mitigation strategies

### 🔴 Milestone 4 – Prototype & Final Submission

*   Demonstrate:
    *   Data acquisition
    *   Data transmission
    *   Processing / inference
    *   Output (alerts, dashboards, actions)

*   Submit final report and documentation

*   Include **security & ethics evaluation**

## 5. Final Deliverables

Each group must submit a complete project dossier including:

### 📄 Documentation

*   Project title and team roles
*   Problem and scenario description
*   PEAS analysis
*   STA analysis
*   DIKW diagram
*   System architecture
*   Hardware & software stack
*   Data pipeline explanation
*   Visualization / decision mechanism
*   Security & ethics analysis
*   Testing plan and results
*   Limitations and future improvements

### 🧪 Evidence

*   Source code or configuration files
*   Images or videos of the system
*   Logs or demonstration output

### 📁 Version Control

*   GitHub repository with:
    *   Version history
    *   Documentation updates
    *   Data and experimental results

## 6. Evaluation Criteria (Rubric)

| Component | Weight | Description                                |
| --------- | ------ | ------------------------------------------ |
| **PEAS**  | 25%    | Clarity of problem and system definition   |
| **STA**   | 25%    | Risk, constraints, and mitigation analysis |
| **DIKW**  | 25%    | Data pipeline from sensor to decision      |
| **S\&E**  | 25%    | Security, privacy, and ethical integration |

👉 Bonus/Penalty:  
±10% based on:

*   Presentation quality
*   Prototype quality
*   Team collaboration

## 7. Peer Assessment and Individual Scores

*   Final grade = **Group score × PAF (Peer Adjustment Factor)**
*   Each student must:
    *   Evaluate themselves
    *   Evaluate teammates

### Evaluation Criteria:

*   Contribution level
*   Work quality
*   Collaboration
*   Responsibility

👉 Evidence must match GitHub logs and project contributions.

## 8. Presentation and Defense

During the final defense, each group must:

1.  Present the problem clearly
2.  Explain the Meta-Framework (PEAS, STA, DIKW, S\&E)
3.  Show system architecture
4.  Demonstrate the prototype
5.  Answer questions on:
    *   Feasibility
    *   Reliability
    *   Security
    *   Ethical impact

👉 The project is evaluated not only on functionality  
but also on **design reasoning and responsibility**.

## 9. Key Success Guidelines

✅ Start from the **problem**, not the technology  
✅ Always justify design decisions  
✅ Keep system **simple but well-structured**  
✅ Document everything clearly  
✅ Think about **risk, privacy, and ethics early**  
✅ Demonstrate **traceability (data → decision)**

## 10. Final Note

A strong project is **not necessarily the most complex one**.  
It is a project that:

*   Clearly defines the problem
*   Builds a coherent system
*   Processes data responsibly
*   Explains decisions transparently

👉 Your goal is to demonstrate **technical competence + responsible design thinking**.
